# WinDnsSyncAgent v1.0.3 版本更新日志

**发布日期**: 2026-06-13<br>
**提交数量**: 2 次提交<br>
**版本类型**: 同步记录排除与 Agent 超时配置增强版本

---

## 📋 版本概述

v1.0.3 聚焦 DNS 同步稳定性与可控性，新增 `excludeRecords` 记录排除配置，允许在同步差异计算前过滤指定解析记录，避免 Legacy Agent 使用 `dnscmd.exe /Additional` 枚举时带出的附加记录被误判为目标端独有记录并反复删除。同时 Go Agent 新增可配置的 PowerShell 执行超时，便于大 Zone 或慢 DNS 环境按需调整内部命令等待时间。

---

## ✨ 新增特性

- 新增 `sync.json` 的 `excludeRecords` 配置，支持按 `zone`、`name`、`type`、`value` 排除指定记录。
- `excludeRecords` 命中规则的源端和目标端记录都会在 diff 前过滤，不参与新增、更新或删除判断。
- Go Agent 新增 `agent.json` 的 `powerShellTimeoutSeconds` 配置，默认 `180` 秒，最大 `3600` 秒。
- Go Agent `/health` 响应新增 `powerShellTimeoutSeconds` 字段，便于确认配置是否生效。

---

## 🐛 Bug 修复

- 修复 Legacy Agent 保留 `/Additional` 枚举时，附加 A 记录可能被同步器误判为目标端独有记录并反复输出 `delete` 的问题。
- 修复 Go Agent 内部 PowerShell 执行超时固定为 `60` 秒，无法与较大的同步端 `requestTimeoutSeconds` 配置对齐的问题。

---

## 🚀 性能优化

- Legacy Agent 的 `dnscmd.exe` 执行方式保持原有直接调用路径，避免为超时控制引入额外进程包装和临时文件开销。
- Go Agent 正常命令执行速度不变，仅将内部 PowerShell 超时从固定值改为可配置值。

---

## 🔧 重构优化

- 同步端新增记录排除匹配逻辑，并复用现有 DNS 名称、记录类型和 IP 值比较规则。
- 配置加载阶段会规范化 `excludeRecords.type` 为大写，并去除 `excludeRecords.zone` 的尾点。
- 为 `excludeRecords` 和 `powerShellTimeoutSeconds` 补充单元测试。

## 🔄 API 变更

本版本无 HTTP API 路径变更。

配置项新增：

- `agent.json.powerShellTimeoutSeconds`：Go Agent 内部单次 `powershell.exe` 脚本执行超时时间，默认 `180` 秒。
- `sync.json.excludeRecords`：同步记录排除规则数组，字段支持 `zone`、`name`、`type`、`value`。

## 🔄 升级说明

从 v1.0.2 升级到 v1.0.3 时，建议同步更新同步执行机和 Go Agent 可执行文件，并同步更新 `config/agent.json` 与 `config/sync.json` 示例配置。

如需保留 Legacy Agent 的 `/Additional` 枚举行为，同时避免附加 A 记录参与同步差异计算，可在 `sync.json` 中增加类似配置：

```json
"excludeRecords": [
  {
    "name": "win2008-around.oa.com",
    "type": "A",
    "value": "10.10.200.253"
  }
]
```

生产环境建议至少配置 `name + type + value`，避免规则过宽导致真实业务记录被排除。

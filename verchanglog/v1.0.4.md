# WinDnsSyncAgent v1.0.4 版本更新日志

**发布日期**: 2026-06-22<br>
**提交数量**: 2 次提交<br>
**版本类型**: Legacy Agent body 接口兼容与同步日志准确性修复版本

---

## 📋 版本概述

v1.0.4 聚焦 Windows Server 2008/2008 R2 Legacy Agent 在跨网段同步时的稳定性，新增 Legacy Agent body 版记录查询与批量同步接口，避免 Zone 名称出现在明文 HTTP URL 路径中触发链路安全策略误拦截。同时优化同步日志输出时机，真实写入模式下仅在批量写入成功返回后输出 `add`、`update`、`delete` 记录日志，降低故障排查时的误判风险。

---

## ✨ 新增特性

- Legacy Agent 新增 `POST /dns/records/query` body 版记录查询接口，Zone 名称通过 JSON body 的 `zone` 字段传递。
- Legacy Agent 新增 `POST /dns/records/batch` body 版批量写入接口，Zone 名称和批次内容均通过 JSON body 传递。
- Legacy Agent 内置轻量 JSON 解析逻辑，`/dns/records/query` 与 `/dns/records/batch` 不再依赖 `.NET System.Web.Extensions`。
- 同步端继续优先调用 body 版接口，旧版 Agent 返回 `404` 时仍会自动回退旧路径接口。

---

## 🐛 Bug 修复

- 修复 Legacy Agent 不支持 `POST /dns/records/query` 时，同步器回退到 `/dns/zones/{zone}/records`，可能因 Zone 名称出现在 URL 路径中被网络安全设备重置连接的问题。
- 修复 Legacy Agent body 版批量接口解析同步器发送的 `null` 批次数组字段时报 `expected JSON array` 的问题。
- 修复真实同步模式下批量写入尚未成功就提前输出 `add`、`update`、`delete` 日志，导致失败排查时误以为记录已经写入成功的问题。

---

## 🚀 性能优化

- Legacy Agent body 版查询和批量写入直接使用脚本内置解析逻辑，避免为同步器固定 JSON 结构加载额外 .NET JSON 组件。
- 批量写入仍保持一次 HTTP 请求处理多条记录，减少逐条提交带来的网络往返开销。

---

## 🔧 重构优化

- Legacy Agent 新增 JSON 字符串反转义、属性值定位、数组拆分和批量结构转换逻辑，专门适配同步器固定的 `zone + batch` 请求结构。
- 同步器将真实写入模式下的记录日志输出移动到 batch 成功返回之后，`dryRun=true` 仍保留计划日志语义。
- 新增同步器单元测试，覆盖 batch 写入失败时不提前记录成功日志的行为。

## 🔄 API 变更

Legacy Agent 新增以下 HTTP API：

- `POST /dns/records/query`：获取指定 Zone 的解析记录，Zone 名称通过 JSON body 的 `zone` 字段传递。
- `POST /dns/records/batch`：批量新增、删除、更新记录，Zone 名称通过 JSON body 的 `zone` 字段传递，批次内容通过 `batch` 字段传递。

旧路径接口继续保留：

- `GET /dns/zones/{zone}/records`
- `POST /dns/zones/{zone}/records/batch`

## 🔄 升级说明

从 v1.0.3 升级到 v1.0.4 时，建议同步更新同步执行机的 `windnssyncagent.exe`，并将新版 `legacy/source-agent.ps1` 部署到所有 Windows Server 2008/2008 R2 Legacy Agent 节点后重启 Agent。

升级后可用以下命令验证 Legacy Agent body 版查询接口：

```powershell
$headers = @{ "X-API-Key" = "YOUR_API_KEY" }
Invoke-RestMethod `
  http://server:8443/dns/records/query `
  -Method Post `
  -Headers $headers `
  -ContentType "application/json" `
  -Body '{"zone":"example.com"}' `
  -TimeoutSec 300
```

如果同步目标端为 Legacy Agent，建议继续使用较小的 `recordBatchSize`，例如 `5` 到 `10`，降低单次批量写入对 2008/2008 R2 DNS 服务和 `dnscmd.exe` 的压力。

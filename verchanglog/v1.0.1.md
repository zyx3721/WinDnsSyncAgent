## 📋 版本概述

v1.0.1 聚焦 DNS 同步稳定性、批量写入可控性和 Windows Server 2008/2008 R2 Legacy Agent 的幂等处理。同步端新增记录批次大小和单次请求超时配置，`mirror` 模式进一步保护排除区域和非业务 Zone；Legacy Agent 在重复新增、重复删除和非同步 Zone 过滤场景下表现更稳健。

---

## ✨ 新增特性

- 新增 `recordBatchSize` 配置，支持控制每批提交到目标 Agent 的记录数量，默认 `50`，最大 `500`。
- 新增 `requestTimeoutSeconds` 配置，支持控制源端和目标端 HTTP 请求超时时间，默认 `90` 秒，最大 `3600` 秒。
- `excludeZones` 支持保护目标端独有 Zone，避免 `mirror` 模式误删显式排除的目标区域。
- 同步逻辑会跳过非业务 Zone 类型，仅同步 `Primary`、`Secondary`、`Stub` 以及类型为空的兼容 Zone。

---

## 🐛 Bug 修复

- 修复 Legacy Agent 新增已存在记录时可能直接报错的问题，现在会识别 `DNS_ERROR_RECORD_ALREADY_EXISTS` 并跳过。
- 修复 Legacy Agent 删除已不存在记录时可能中断同步的问题，现在会识别 `DNS_ERROR_NAME_DOES_NOT_EXIST` 并跳过。
- 修复 `mirror` 模式下目标端命中 `excludeZones` 的独有 Zone 仍可能被纳入删除判断的问题。
- 优化 Zone 创建和删除结果记录顺序，确保实际写入成功后再记录执行结果。

---

## 🚀 性能优化

- 同步记录写入改为按 `update`、`add`、`delete` 分阶段分批提交，降低大批量记录触发 HTTP 超时或 PowerShell 长耗时的风险。
- 针对 Windows Server 2008/2008 R2 Legacy Agent 场景，可将 `recordBatchSize` 调低到 `5` 到 `10`，配合更长超时时间提升大 Zone 同步成功率。

## 🔄 API 变更

本版本未新增或删除 HTTP API。同步程序仍主要使用以下批量写入接口：

- `POST /dns/zones/{zone}/records/batch`：批量新增、删除、更新解析记录。

行为变化：同步端会按 `recordBatchSize` 将记录分批提交到该接口，并按 `requestTimeoutSeconds` 控制每次 HTTP 请求的超时时间。

## 🔄 升级说明

从 v1.0.0 升级到 v1.0.1 时，建议同步更新可执行文件、`agent.ps1`、`sync.ps1`、`sync.cmd`、`agent.cmd`、`legacy/source-agent.ps1` 和 `config/sync.json` 示例配置。

已有 `config/sync.json` 可继续使用。若目标端为 Windows Server 2008/2008 R2 Legacy Agent，建议按环境规模补充以下配置：

```json
"recordBatchSize": 5,
"requestTimeoutSeconds": 300
```

目标端为 Windows Server 2012+ Go Agent 时，一般可使用默认值：

```json
"recordBatchSize": 50,
"requestTimeoutSeconds": 90
```
